Result rows of {0,number,#} bytes exceed maxResultBuffer={1,number,#} bytes. The limit keeps the rows of one result from taking more client memory than that. The driver has closed the connection, so open a new one. To read this many rows, turn autocommit off and call Statement.setFetchSize: the driver then reads the result in batches of that many rows and applies the limit to each batch. You can also select fewer rows or columns. To allow results this large, raise the maxResultBuffer connection property above {0,number,#} bytes. It accepts a byte count, a size with a decimal suffix such as 500M, or a percent of the maximum heap such as 20p. The driver reduces any value above 90% of the maximum heap to that amount, so a larger limit can also need a larger -Xmx.
