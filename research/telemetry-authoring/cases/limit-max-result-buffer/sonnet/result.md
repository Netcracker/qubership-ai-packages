Result set exceeds maxResultBuffer: the rows read so far take {0,number,#} bytes, and the limit is {1,number,#} bytes. The limit stops the rows of one result from using more client memory than that. The driver has closed the connection, so open a new one. To read this result as it is, set the maxResultBuffer connection property (a JDBC URL parameter or a DataSource property) to more than {0,number,#} bytes. It accepts a byte count such as 100000000, a size such as 100M, or a percent of the maximum heap such as 10p, and the driver clamps it to 90% of the maximum heap. Alternatively, turn autocommit off and call Statement.setFetchSize with a value whose batch of rows fits within the limit, so the driver reads the result in batches and counts each batch from zero. You can also select fewer rows or columns.
