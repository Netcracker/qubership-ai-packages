Result rows exceed maxResultBuffer: the rows read so far take {0,number,#} bytes, and the limit is {1,number,#} bytes. The limit keeps the rows of one result from using more client memory than you allow. The driver has closed the connection, so open a new one. To stay under the limit, select fewer rows or columns, or turn autocommit off and call Statement.setFetchSize, so the driver reads the result in batches that each count from zero. To allow more, set the maxResultBuffer connection property above {1,number,#} bytes (the driver caps it at 90% of the maximum heap), or remove the property to turn the limit off.
