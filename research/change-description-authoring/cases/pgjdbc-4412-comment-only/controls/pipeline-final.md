Since 42.7.13 (PR #4114), `PGXAConnection` leaves the caller's `autoCommit` flag alone instead of saving and restoring it around each `XAResource` call. Several comments and two test names still describe the old behavior. The `State.ACTIVE` Javadoc says "autoCommit is false on a connection returned by getConnection", and the comment in `getConnection()` says the same for a branch in progress, though nothing sets the flag to `false` any more. The `recover_withAutoCommitFalse_doesNotOpenTransaction` Javadoc treats "2nd phase commit must be issued using an idle connection" as a live precondition, though that message was removed in the same change. `restoreOfAutoCommit` and `restoreOfAutoCommitEndThenJoin`, with their assertion messages, check a restore that no longer happens.

Two other comments contradicted the code next to them. The `recover()` comment said the WHERE clause filters by `current_user`, while the query keeps rows for which `pg_has_role(current_user, owner, 'member')`. A batch test called the receive-buffer limit 64 KB, while `QueryExecutorImpl.MAX_BUFFERED_RECV_BYTES` is `64000`.

The two tests become `onePhaseBranch_leavesAutoCommitUnchanged` and `endThenJoinBranch_leavesAutoCommitUnchanged`, and their messages name the value each case expects. The class Javadoc no longer lists the XA statements one by one: it says every statement the class issues goes through `execSQLUpdate` or `execSQLQuery`, which a new statement cannot make stale, and it carries the `QUERY_SUPPRESS_BEGIN` rationale that four call-site comments repeated. The rest of the edits are wording.

Nothing changes at run time. Apart from the renamed tests and their assertion messages, the only non-comment line the diff touches is `Arrays.toString(recovered);`, whose trailing comment moved to the line above. That statement has no effect and stays, because removing it is a code change.
