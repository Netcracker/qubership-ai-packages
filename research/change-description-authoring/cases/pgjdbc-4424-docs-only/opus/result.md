`TESTING.md` §5 "Extending the test suite with new tests" told contributors that most tests used JUnit 4 and that they should add each new test class to the test suite. The pull request template asked "Have you added your new test classes to an existing test suite in alphabetical order?". Every test under `pgjdbc/src/test` uses JUnit 5, and Gradle finds test classes without a suite class, so contributors had no suite to add their tests to. A JUnit 4 test under `pgjdbc` also fails to compile, because [`pgjdbc/build.gradle.kts`](https://github.com/pgjdbc/pgjdbc/blob/f171cd8af6fc5f341c765309af0c1ab0db6fbfb7/pgjdbc/build.gradle.kts#L157-L162) rejects `junit:junit` on the test compile classpath.

[TESTING.md §5 Extending the test suite with new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#5---extending-the-test-suite-with-new-tests) now tells contributors to write new tests with JUnit 5. It names the two modules that keep JUnit 4 tests because they need a JUnit 4 runner: `pgjdbc-junit4-test` (classloader-leak-test) and `pgjdbc-osgi-test` (Pax Exam). [§6 Guidelines for developing new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#6---guidelines-for-developing-new-tests) now refers to JUnit 5 `Assertions` instead of JUnit 4 `Assert`.

The template asked about tests in both "New Feature Submissions" and "Changes to Existing Features". The new [Tests and style](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/.github/pull_request_template.md#tests-and-style) section asks these questions once for every pull request. It also adds a question: does a bug fix's new test fail without the fix? The item asking for an explanation of the changes moves to "All Submissions", since it applies to every pull request.

`git grep -lE 'org\.junit\.(Test|Assert|runner)' -- pgjdbc/src/test` on `master` prints nothing. The same search over the whole repository finds files only under `pgjdbc-junit4-test` and `pgjdbc-osgi-test`.
