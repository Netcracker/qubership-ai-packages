TESTING.md said that most tests are written with JUnit 4 and told contributors to add a new test class to the test suite. The pull request template also asked whether new test classes were added to an existing test suite in alphabetical order. Every test under `pgjdbc/src/test` is now JUnit 5, and Gradle finds test classes without a suite class. Both instructions sent contributors looking for a suite that does not exist.

[TESTING.md §5 Extending the test suite with new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#5---extending-the-test-suite-with-new-tests) now says to write new tests with JUnit 5 under `pgjdbc/src/test/java/org/postgresql`. It also names the two modules that keep JUnit 4 tests because they need a JUnit 4 runner: `pgjdbc-junit4-test` for the classloader-leak-test runner, and `pgjdbc-osgi-test` for Pax Exam. In [§6 Guidelines for developing new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#6---guidelines-for-developing-new-tests), the JUnit 4 `Assert` examples are replaced with JUnit 5 `Assertions`.

The template asked about tests in two sections, "New Feature Submissions" and "Changes to Existing Features". A single [Tests and style](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/.github/pull_request_template.md#tests-and-style) section now asks four things: whether the tests cover the changes, whether a bug fix's new test fails without the fix, whether the tests pass locally, and whether `./gradlew styleCheck` passes. The item that asks for an explanation of what the changes do moves to "All Submissions" because it applies to every pull request.

This change is documentation only, and no test was added or run. I checked the claims about the code in two ways. On `master`, `git grep -lE 'org\.junit\.(Test|Assert|runner)' -- pgjdbc/src/test` finds no files. The same search over the whole repository finds files only under `pgjdbc-junit4-test` and `pgjdbc-osgi-test`. Also, [`pgjdbc/build.gradle.kts` lines 157–162](https://github.com/pgjdbc/pgjdbc/blob/f171cd8af6fc5f341c765309af0c1ab0db6fbfb7/pgjdbc/build.gradle.kts#L157-L162) reject `junit:junit` on the test compile classpath, so a JUnit 4 test under `pgjdbc` does not compile.
