[TESTING.md §5 Extending the test suite with new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#5---extending-the-test-suite-with-new-tests) now says that new tests use JUnit 5 and go under `pgjdbc/src/test/java/org/postgresql`, with no suite class to register them in. It names the two modules that keep JUnit 4 because they need a JUnit 4 runner: `pgjdbc-junit4-test`, which holds the class-unloading test that needs the JUnit 4 runner of the classloader-leak-test library, and `pgjdbc-osgi-test`, which holds the OSGi tests on Pax Exam. The paragraphs about test suites and test cases go with the suite instructions. [§6 Guidelines for developing new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#6---guidelines-for-developing-new-tests) swaps the JUnit 4 `Assert` examples for JUnit 5 `Assertions`.

The template's two test items, one under "New Feature Submissions" and one under "Changes to Existing Features", become a single "Tests and style" section. It asks whether the changes are covered by tests, whether a bug fix's new test fails without the fix, whether the tests pass locally, and whether `./gradlew styleCheck` passes. The item about explaining the change moves to "All Submissions", since it applies to every pull request.

Documentation only; no code changes.
