The [TESTING.md §5 Extending the test suite with new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#5---extending-the-test-suite-with-new-tests) section says most tests are JUnit 4 and tells contributors to add a new test class to the test suite. The pull request template asks whether new test classes were added to a suite in alphabetical order. Both are out of date. Every test under `pgjdbc/src/test` is JUnit 5 now, and Gradle discovers test classes without a suite class, so a contributor who follows either instruction looks for a suite that does not exist. A JUnit 4 test under `pgjdbc` also does not compile, because [`pgjdbc/build.gradle.kts` lines 157 to 162](https://github.com/pgjdbc/pgjdbc/blob/f171cd8af6fc5f341c765309af0c1ab0db6fbfb7/pgjdbc/build.gradle.kts#L157-L162) reject `junit:junit` on the test compile classpath.

The section now says that new tests use JUnit 5 and go under `pgjdbc/src/test`. It names the two modules that keep JUnit 4 because they need a JUnit 4 runner: `pgjdbc-junit4-test`, which holds the class-unloading test that needs the JUnit 4 runner of the classloader-leak-test library, and `pgjdbc-osgi-test`, whose OSGi tests run on Pax Exam. The template drops the suite question and asks its test questions in one "Tests and style" section.

Nothing was built or run, and no test was added. The checks are searches of the source tree: `git grep -lE 'org\.junit\.(Test|Assert|runner)' -- pgjdbc/src/test` on `master` prints nothing, and the same search over the whole repository finds files only under `pgjdbc-junit4-test` and `pgjdbc-osgi-test`.
