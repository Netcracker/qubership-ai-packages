TESTING.md says most tests are written with JUnit 4 and tells contributors to add a new test class to the suite. The pull request template asks whether new test classes were added to a suite in alphabetical order. Both instructions point at something that no longer exists. Every test under `pgjdbc/src/test` is JUnit 5, and Gradle discovers test classes without a suite class. The build also rejects `junit:junit` on the test compile classpath, so a JUnit 4 test added under `pgjdbc` does not compile.

`TESTING.md §5 Extending the test suite with new tests` now says to write new tests with JUnit 5 under `pgjdbc/src/test/java/org/postgresql`, and that Gradle finds them with no suite to register them in. It names the two modules that keep JUnit 4 because they need a JUnit 4 runner: `pgjdbc-junit4-test`, which holds the class-unloading test that uses the JUnit 4 runner of the classloader-leak-test library, and `pgjdbc-osgi-test`, which holds the OSGi tests that run on Pax Exam. The JUnit 4 `Assert` examples in `TESTING.md §6 Guidelines for developing new tests` become JUnit 5 `Assertions` examples.

The template asked about tests in both the "New Feature Submissions" and "Changes to Existing Features" sections. A single "Tests and style" section now asks whether the changes are covered by tests, whether a bug fix's new test fails without the fix, whether the tests pass locally, and whether `./gradlew styleCheck` passes. The suite question is removed. The "explanation of what your changes do" item moves to "All Submissions", since it applies to every pull request.

No code changed, and no test was added or run. Two checks support the claims above. `git grep -lE 'org\.junit\.(Test|Assert|runner)' -- pgjdbc/src/test` prints nothing on `master`, and the same search over the whole repository finds files only under `pgjdbc-junit4-test` and `pgjdbc-osgi-test`. The `junit:junit` rule in [`pgjdbc/build.gradle.kts` lines 157 to 162](https://github.com/pgjdbc/pgjdbc/blob/f171cd8af6fc5f341c765309af0c1ab0db6fbfb7/pgjdbc/build.gradle.kts#L157-L162) is what stops a JUnit 4 test under `pgjdbc` from compiling.
