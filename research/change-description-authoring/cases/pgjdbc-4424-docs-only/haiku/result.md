TESTING.md says most tests are JUnit 4 and tells contributors to add a new test class to a test suite. The pull request template asks whether new test classes were added to a suite in alphabetical order. Neither matches the repository now. The tests under `pgjdbc/src/test` use JUnit 5, and Gradle finds test classes without a suite class, so a contributor who follows either instruction looks for something that does not exist.

The [TESTING.md §5 Extending the test suite with new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#5---extending-the-test-suite-with-new-tests) section now says new tests use JUnit 5 and go under `pgjdbc/src/test/java/org/postgresql`, with no suite to register them in. It names the two modules that keep JUnit 4 tests, `pgjdbc-junit4-test` and `pgjdbc-osgi-test`, and says a test belongs in one of them only when it needs a JUnit 4 runner. The assertion advice in [§6 Guidelines for developing new tests](https://github.com/pgjdbc/pgjdbc/blob/e6bf0181251063d4cb2fc8324e28fc4f6cde1313/TESTING.md#6---guidelines-for-developing-new-tests) now points to JUnit 5 `Assertions`. The pull request template moves the test items of both feature sections into one "Tests and style" section, and moves the explanation item to "All Submissions", since it applies to every pull request. The change touches only documentation and the template.

The claims about the tests rest on two checks, not on a test. `git grep -lE 'org\.junit\.(Test|Assert|runner)' -- pgjdbc/src/test` on `master` prints nothing, and the same search over the whole repository finds files only under `pgjdbc-junit4-test` and `pgjdbc-osgi-test`. A JUnit 4 test under `pgjdbc` does not compile, because [`pgjdbc/build.gradle.kts` lines 157 to 162](https://github.com/pgjdbc/pgjdbc/blob/f171cd8af6fc5f341c765309af0c1ab0db6fbfb7/pgjdbc/build.gradle.kts#L157-L162) reject `junit:junit` on the test compile classpath.
