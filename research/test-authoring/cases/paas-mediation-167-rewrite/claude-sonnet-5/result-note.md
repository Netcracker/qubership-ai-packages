## Message for the PR author

I audited the tests this commit added/changed in `route_test.go` against the `test-authoring` skill before changing anything. I ran the production code through the specific mutations your commit message claims each test catches (`%w`→`%v` in both single-mode branches of `resolveRouteResult`, each branch of `dualModeDeleteError`, and the summary-formatter revert in `dualModeRouteError`): every one of those mutants turns exactly the test you named red, and the whole suite is green on the real code. The tests are doing real work — this was the strong part of the commit.

What I rewrote: six of the new tests built a `require.New(t)` assertions object and then ran two or three independent checks through it (`ErrorIs` twice, or `ErrorIs` + `ReasonForError` + a `Contains` on the hint text). `require` aborts the test on the first failed assertion, so if `ErrorIs(err, httpRouteForbidden)` ever fails, you'd never learn whether `ErrorIs(err, ingressExists)` also failed — exactly the "report every mismatch" rule in the skill's §7. None of these had a real "continuing is meaningless" reason to abort early (no nil dereference follows a failed check), except the implicit risk of `err.Error()` panicking on a nil `err` in a couple of them. So I split each into a `require.Error(t, err)` guard (the actual point where continuing would be meaningless, since the next line calls `err.Error()`) followed by plain `assert.*` calls for the independent facts. I verified the fix does what it's supposed to: I broke both the hint text and the error-wrapping in `dualModeRouteError` at once and confirmed the rewritten test now reports both failures in one run instead of hiding the second behind the first. Added the `testify/assert` import the file didn't have yet; touched no other test in the file, since the rest of `route_test.go` already uses the `require.New(t)` shape throughout and that's out of this commit's scope.
