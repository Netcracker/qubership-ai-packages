# Renovate APM dependency updates

Renovate tracks APM package references in `apm.yml` files through its built-in `apm` manager and the shared
[`Netcracker/renovate-config:apm`](https://github.com/Netcracker/renovate-config/blob/main/apm.json) preset. The
repository-local `renovate.json` enables that preset and turns off its regex manager for `agent-packages/*/apm.yml`,
because that manager's update writes `#<new tag>` and drops the commit SHA.

## What Renovate updates

Renovate scans every `apm.yml` file and updates these APM reference formats:

- Package dependencies pinned to the commit of a release tag, with the tag in a comment, such as
  `Netcracker/qubership-workflow-hub/agent-packages/qubership-workflow-hub-usage#<sha>  # v2.8.2`. Renovate moves the
  SHA and the tag to the newest release together. The tag versions the whole repository, so Renovate proposes a bump
  for every release of it, including a release that leaves the package unchanged. Pin the commit, not the tag alone:
  `tests/marketplace_roundtrip.sh` rejects a ref that is not a commit SHA.
- Marketplace entries that use `source`, `subdir`, and `ref` fields in the root `apm.yml`.

Renovate groups these updates into an `apm packages` PR.

Renovate leaves these references as written:

- A dependency on another package in this repository, written as `../<name>`. It resolves at the commit the dependent
  package is installed from.
- A dependency pinned to a branch, either directly, such as `#main`, or in a comment after a commit, such as
  `#<sha>  # feat/agent-packages`. For a branch in a comment, the Dependency Dashboard reports
  `Could not determine new digest for update (github-tags package <owner>/<repo>)`. Use a branch only for a package
  that has no release yet, and pin the commit of the release tag once there is one.
- A dependency pinned to a commit with no comment.
- A dependency written with `@` instead of `#`, such as
  `Netcracker/qubership-ai-packages/agent-packages/codex-review@v1.0.0`.

`make test` fails when a package in `agent-packages/` depends on another repository without a `#<sha>  # <tag>` pin,
unless `UNRELEASED_DEPENDENCIES` in `tests/renovate-policy/test_renovate_policy.py` lists the dependency.

## Why APM updates do not automerge

The root `apm.yml` is the source of truth for marketplace packages, but
[`.claude-plugin/marketplace.json`](../.claude-plugin/marketplace.json) is generated by `apm pack`. Mend-hosted
Renovate cannot run repository-local `postUpgradeTasks`, so it cannot regenerate the marketplace index in the PR.

For that reason, the shared `apm` preset sets `automerge: false` for `depType: apm`. APM update PRs must stay
manual even when the change looks like a low-risk `digest` update. The marketplace validation workflow also runs
`apm pack --check-clean --dry-run` and fails when `apm.yml` and the committed marketplace index drift.

The first marketplace validation run on an APM Renovate PR is therefore expected to fail when Renovate changes the
root `apm.yml`. The `validate` job reports the marketplace drift, and `Marketplace Gate` propagates that failure until
the generated index is committed.

## How to finish a Renovate APM PR

1. Review the changed APM references in `apm.yml` files.
1. Ignore unrelated generated or documentation changes when comparing against a manually prepared update PR.
1. Regenerate the marketplace index:

   ```bash
   apm pack
   ```

1. Commit the regenerated `.claude-plugin/marketplace.json` with the Renovate branch.
1. Let the marketplace validation workflow pass before merging.

If Renovate updates only nested package manifests and not the root marketplace `apm.yml`, still run the validation
workflow. Package version bumps may require a matching root marketplace version entry before the release can pass
`apm pack --check-versions`.
